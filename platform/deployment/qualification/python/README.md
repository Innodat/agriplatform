# Python baseline qualification fixture

This ENV-only fixture resolves and executes the Python subset of the
[approved baseline](../../../docs/architecture/contracts/scaffold-dependency-baseline-2026-10-14.md).
It is not a shared application package, service implementation, runtime requirements
owner or generator input. Applications/services retain their own subsets and locks.
Never import this fixture from a runtime owner. Pytest is test-only.

The checked-in `uv.lock` is generated by selected uv0.13.1, with all transitive versions
and publisher artifact hashes. Do not hand-edit it. Qualification currently covers
ordinary CPython3.15.0 on Linux x86_64 GNU; it does not qualify other platforms or
container images. The graph contains32 installed packages plus the virtual fixture.

From repository root, run this complete Bash block. It uses already qualified tools
from run0cc4bc48-505e-41c1-8876-25b2d49b5694 and creates a private, unique proof directory.
Both virtualenv destinations must be absent. The subshell stops immediately on a failed
check/install/test; it cannot continue with stale dependencies after a lock failure.
No application or preexisting virtualenv is reused or removed.

```bash
(
set -eu
umask 077
ENV_TOOLS="$PWD/platform/deployment/.local/kdg-toolchains/0cc4bc48-505e-41c1-8876-25b2d49b5694/payload"
ENV_FIXTURE="$PWD/platform/deployment/qualification/python"
ENV_PARENT="$PWD/platform/deployment/.local/python-baseline-qualification"
ENV_CACHE="$ENV_PARENT/cache"
mkdir -p "$ENV_PARENT"
ENV_PROOF_ROOT="$(mktemp -d "$ENV_PARENT/proof-XXXXXXXX")"
ENV_FIRST_VENV="$ENV_PROOF_ROOT/first/venv"
ENV_SECOND_VENV="$ENV_PROOF_ROOT/second/venv"

# Check source/lock agreement before any environment synchronization.
env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 UV_CACHE_DIR="$ENV_CACHE" \
  "$ENV_TOOLS/uv/uv" lock --check --project "$ENV_FIXTURE" \
  --python "$ENV_TOOLS/python/bin/python3" --no-python-downloads --no-config \
  --default-index https://pypi.org/simple

test ! -e "$ENV_FIRST_VENV"
test ! -L "$ENV_FIRST_VENV"
env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 UV_CACHE_DIR="$ENV_CACHE" \
  UV_PROJECT_ENVIRONMENT="$ENV_FIRST_VENV" "$ENV_TOOLS/uv/uv" sync \
  --project "$ENV_FIXTURE" --python "$ENV_TOOLS/python/bin/python3" \
  --frozen --no-build --link-mode copy --no-install-project --group test \
  --no-python-downloads --no-config --default-index https://pypi.org/simple

env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  "$ENV_FIRST_VENV/bin/python" -I -B -m pytest -q -p no:cacheprovider \
  -c "$ENV_FIXTURE/pyproject.toml" --confcutdir "$ENV_FIXTURE" "$ENV_FIXTURE/tests"

# Independent second environment, with registry access disabled during installation.
test ! -e "$ENV_SECOND_VENV"
test ! -L "$ENV_SECOND_VENV"
env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 UV_CACHE_DIR="$ENV_CACHE" \
  UV_PROJECT_ENVIRONMENT="$ENV_SECOND_VENV" "$ENV_TOOLS/uv/uv" sync \
  --project "$ENV_FIXTURE" --python "$ENV_TOOLS/python/bin/python3" \
  --frozen --offline --no-build --link-mode copy --no-install-project --group test \
  --no-python-downloads --no-config --default-index https://pypi.org/simple

env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  "$ENV_SECOND_VENV/bin/python" -I -B -m pytest -q -p no:cacheprovider \
  -c "$ENV_FIXTURE/pyproject.toml" --confcutdir "$ENV_FIXTURE" "$ENV_FIXTURE/tests"

printf 'ENV proof retained at %s\n' "$ENV_PROOF_ROOT"
)
```

`lock --check` rejects manifest drift; `sync --frozen` alone does not verify that
manifest and lock agree. The check may fetch metadata but cannot update the checked-in
lock. With a warm metadata cache, adding `--offline` to the check is supported. The first
sync downloads wheels if absent; the second is explicitly offline. Both installations
use `--no-build`, so metadata availability is not substituted for native execution.

Deliberate lock regeneration after a reviewed manifest change uses the same selected
uv/Python/cache/index command with `lock` and without `--check --offline`. Record changed
pins and affected evidence; do not silently downgrade the approved baseline. No implicit
Python download, global package install, HOME override, application config or ambient
pytest plugin/proxy is used. The tests bind only an ephemeral loopback HTTP socket;
socket-restricted sandboxes must grant that narrow execution or the test fails.

The tests verify exact direct package/runtime versions, native Pydantic/Psycopg/libpq,
valid/invalid HTTP requests over actual Uvicorn/HTTPX, settings validation, selected JWT
signature/issuer/audience/expiry/algorithm checks, canonical JSON and PostgreSQL/Alembic
offline SQL. They do not connect to a database, execute schema changes, qualify Identity
authorization or implement an owner HTTP contract. No real user or application content
is used. See [delivery evidence](../../ENV_PYTHON_BASELINE_EVIDENCE.md) for traceability,
red/green results, hashes, impacts and remaining runtime gates.
