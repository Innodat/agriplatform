# Adversarial seam review

Reviewed: 2026-10-21. Scope: `ARCHITECTURE-SPINE.md`, checked against `SPEC.md` and `ux-behaviour.md`. Review only; no source changes.

## Verdict

**PASS as a feature architecture spine with binding pre-implementation gates.** No blocking invariant hole or contradiction was demonstrated in the requested seams. This is not implementation readiness: D-1–D-3 must close before their consumers, D-4 before final interaction acceptance, and D-5 before activation/readiness claims. The document expressly authorizes no runtime implementation.

The attack criterion was two independently built units that both obey every applicable AD and still produce incompatible behavior. A consumer independently choosing a wire format that D-2 explicitly centralizes does not satisfy that criterion: it violates the gate. Unchosen endpoints, revision encodings, retained metadata, channel selection and role provisioning are therefore not findings merely because they remain unchosen.

## Highest-priority gate checks — not defects in this draft

1. **D-2 must remain genuinely singular.** Before editor/highlight/persistence work, require the same owned contract to define whole-note revisions, replay receipts, branch evidence, source-anchor validation and private-response/copy/deletion representation. Separate frontend and database definitions would undo AD-6/AD-8/AD-9 even if each looked locally reasonable.
2. **D-1 must supply executable lifecycle semantics.** Concurrent acceptance/revocation, deadline equality, verified target binding, suspension and explicit reissue need shared outcomes before invitation consumers start. The spine correctly assigns them; it does not claim the legacy Access check already supplies them.
3. **D-3 must prove scope isolation across delivery, inbox details, unread counts and read-state mutation.** Account scope must never become a synthetic organization or a fallback after organization denial. Delivery deduplication must not mutate share authority.
4. **D-5 must prove the public/private split under failure and ordinary rollout.** Qualification should exercise public routes with private configuration unavailable, restricted credentials and pool reuse, previous-version compatibility, migration failure and committed-intent/provider failure independently. Prose separation alone is not release evidence.

## Limits

This review evaluates the consistency contract, not implementation security or operational readiness. No tests were executed because the reviewed artifacts are planning documents and the requested work is review only. Gate closure must supply concrete contracts and evidence; this PASS cannot be reused as their approval.
