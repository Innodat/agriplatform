## Method and practical limits

A bounded item has one actual producer/query/UI/journey outcome, declared current owner
contracts and concrete completed predecessors. It reuses actual state/receipt/commitment/
source/due/Content primitives rather than hides another service or algorithm in the item.
A browser item consumes its complete API; a journey fills actual composition only. Count
minimal first-use read/presentation and same-item neutral scaffold/test promotion when
applicable. Multiple cases alone do not justify copying a feature into multiple stories.

`Retain — bounded` means the declared delta fits one agent with the stated completed
predecessors and affected tests. `Retain — focused verification` has denser native/
concurrency/owner-protocol evidence and must stay tightly within the explicit exclusions.
These are qualitative planning judgments, not measured hours/tokens or test PASS. If an
actual predecessor is absent, implement its existing owning item first; do not inflate
this consumer or call the prerequisite free. If a concrete additional responsibility
appears during readiness, return the precise material split to the user.

No further split is justified by the currently bound E5 delta alone. In particular, the
People selected/planned consumer consumes earlier actual source selection/schedule/attempt
semantics; it does not implement a source batch engine. The first expiry consumer extends
actual E3 worker mechanics; it does not deliver the receiver/inbox/outbox infrastructure.
The finalizer consumes real completed rule/effect providers, not every source service.
These exclusions are enforceable scope limits, not waivers of actual integration proof.
