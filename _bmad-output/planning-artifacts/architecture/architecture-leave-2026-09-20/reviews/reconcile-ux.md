# Leave architecture reconciliation — UX input

**Date:** 2026-09-23  
**Scope:** Independent reconciliation of current Leave DESIGN/EXPERIENCE, shared platform EXPERIENCE, and applicable latest accepted ADRs. ## Verdict and comparison boundary

The UX contracts provide usable architecture constraints for permissions, authoritative calculations, asynchronous recovery, drafts, navigation, accessibility and localization. Their approved composition does not require a separate shared task/workflow engine or a cross-application business database. One obsolete rounding sentence was reconciled with an already accepted decision; no new product choice was required.

The initial inspection saw a 25-line destination placeholder. A second pass reviewed the completed draft with AD-1–AD-13. Its rules preserve the UX ownership, authorization, calculations, acknowledgement, drafts, content, notification, localization and recovery requirements below. In particular AD-7 retains independent finalization gates, AD-8 covers create/resume and late-save protection, AD-9 covers attachment association, and AD-12 inherits the approved accessible responsive contract. The dependency/error, identity, privacy and effective-date conventions also align.

**Current reconciliation: no unresolved UX-to-spine contradictions.** Detailed focus/filter/navigation and privacy rules remain binding through the explicitly authoritative UX companions rather than being duplicated in every AD. Concrete protocols and runtime evidence are gated before affected stories, not claimed complete.
## Concrete source conflict

**UX-R1 — medium, resolved during reconciliation: stale conditional rounding control.** Leave EXPERIENCE, “Leave-type and policy configuration,” advanced-controls paragraph says **“Enabling proration reveals rounding.”** Earlier in the same section it says **“Remove the rounding selector”**, matching accepted Leave ADR-0103, which supersedes ADR-0026's selectable rounding. The newer rule is authoritative: full precision with fixed final usable whole-minute floor and retained cumulative remainders; no configurable nearest/up/down field or API choice. The parent authorized the exact source correction: the paragraph now specifies the fixed final whole-minute convention with no rounding selector. Do not carry it into a policy schema, generated contracts or component requirements, and do not amend accepted historical ADR text.

## Constraints to preserve in the architecture

| Area | Binding UX/domain consequence | Architecture implication / acceptance boundary |
|---|---|---|
| Ownership and API | Shared identity is reused; Leave owns employment settings, supervisor assignment, policies, calculations, approval execution and report definitions. Shared controls do not grant authority. | Browser business reads/commands use Leave FastAPI with Pydantic/OpenAPI and generated/validated TypeScript contracts (platform ADR-0001). Shared runtime services use HTTP; no server imports or cross-owner runtime tables. Reuse UI primitives without moving Leave business logic into them. |
| Authoritative balances | My Leave shows corrected current balances, available/reserved distinctions and explanation; Apply shows date-specific projections. Exploring dates reserves nothing. | Use one authoritative backend calculation for read, preview and confirmation. Follow ADR-0090/0106: automatic earning is derived on demand, not dependent on accrual posting jobs; immutable actual events and decision evidence remain. No independent frontend accrual calculator, mandatory snapshot on every read, or double-counted derived/projected earning. |
| Historical evidence | Current balance and original **Balance at approval** are different facts. Corrections retain actor/reason, original evidence and affected-request safeguards. | ADR-0107/0111 require retained immutable inputs/version references, calculation version distinct from policy version, and snapshot/action atomicity. Privacy filtering also applies to explanation/snapshot JSON, not just ordinary request DTOs. No historical-code execution framework is required. |
| Effective policy dates | Daily/monthly/upfront rate changes have different effective dates; availability-method switches and employee recurring overrides have their own period-boundary rules. | Preview API must return employee-specific effective/usable dates and distinguish preserved overrides; a single universal effective date cannot represent different anniversaries. Follow ADR-0098–0105 and ADR-0083, preserving anchored monthly periods and fixed rounding. UI examples are not the calculation source. |
| Privacy and access | My Leave/Approvals/Manage Leave share active NGO and session but have independent capabilities. Assigned approvers see in-scope types/notes; medical metadata/content has separate permission. Colleague calendars conceal all type/reason detail. | Authorize lists, counts, filter options, search, explanations, audit, exports, details and signed reads independently. Do not leak hidden types through colors/groupings/tooltips or retained caches. Leave Manager is NGO-wide in MVP but not automatically an approver. Recheck current access after navigation and before writes. |
| Combined and temporary authority | Shared role grants combine with scope; missing a grant in one role is not a deny. Temporary appointments grant bounded Leave authority, not a permanent role or document access. | Keep role administration in shared access management and step/resource rules in Leave. Validate dated membership, assignment, self-approval and special absence-fallback scope. Role deletion requires a current zero-holder check, retained history, and refresh on return from holder editing. |
| Employee acknowledgement | Self-service unpaid requests require exact-amount acknowledgement before submission. ADR-0088 permits manager submission first; only the employee may acknowledge, and finalization waits even if the submitting manager owns the sole approval step. | Store approval-step outcomes separately from finalization gates and allocation. Acknowledgement validates the current amount/version; it is neither approval nor a second draft. Otherwise-valid intermediate steps may proceed; final consumption occurs exactly once after all gates. Do not overwrite the employee's active draft or repeat a valid approval merely because consent arrives later. |
| Draft ownership and concurrency | One employee draft per NGO, autosaved; Close does not discard; saved status reflects acknowledged edits only. Concurrent tabs cannot silently overwrite one another. | ADR-0118 and platform ADR-0033/0034 require database-enforced create-or-resume, explicit revisions/editability checks, serialized same-tab saves, lifecycle conflicts distinct from revision conflicts, and no upsert/resurrection after submit/discard. Draft closure/request/reservation/audit/outbox local effects commit atomically. Old create retries must not become a new active draft. |
| Review and confirmation | Administrative edits use explicit Review/Confirm; prior previews cannot authorize changed consequential results. Ordinary typing gets no mandatory review screen. | Validate record revision **and relevant calculation dependencies** under ADR-0112. Changed consequential duration/allocation returns a refreshed review preserving input; irrelevant changes do not demand needless confirmation. Coordinate configuration writers as well as employee balance writers. Release transaction coordination before human review. |
| Busy versus uncertain result | Bounded contention preserves form and gives a known-uncommitted retry; network uncertainty checks operation status first. | ADR-0113 and shared operation identity distinguish busy, stale review, validation failure, access denial and unknown outcome. Do not present unknown commit status as definite failure or start an unrelated mutation on retry. Stable machine-readable errors and typed safe details drive behavior (platform ADR-0031); never parse localized text. |
| Lifecycle correction | Cancel original and submit replacement must preserve original approval on replacement validation failure. Rejected replacement leaves original cancelled and produces follow-up. | Define local atomicity and duplicate-safe combined commands. Resubmission preserves request ID with fresh approval cycle; approved correction uses linked new request. Cancellation includes historical cap/expiry effects, not unconditional arithmetic restoration. |
| Content attachment | Uploaded bytes are not yet an attached document. Optional failed files cannot silently disappear; required association/readiness blocks submission. | Content Service owns content; Leave owns associations and request checks. Platform ADR-0030 requires recoverable **Attaching…**, reusable content ID/operation identity, ownership validation, cleanup/association coordination and honest expired-content errors. No cross-service transaction or long business lock around HTTP calls. Protect saved-draft and submitted attachments from cleanup. |
| Notifications | Unread is not unresolved work; NGO selector exposes authorized counts only. Notifications describe dated events; links reveal current authorized state. | Maintain per-user/NGO read state independently of work gates. Leave owns transactional outbox/relevance, shared capability owns delivery. ADR-0116/0117: skip obsolete unhanded action intents with reasons, never claim local skip recalls remotely accepted work, do not promise email order. Request notifications stay minimal; ADR-0101's ordinary entitlement-change amounts are a distinct message contract, not permission to disclose request notes/types. |
| Session recovery | Renew first; interactive sign-in returns to prior authorized NGO/page/record/filter/form context, honestly recovering saved values. Authentication outage is not proof of revoked permission. No unapproved durable local store of sensitive forms. |

## Frontend and accessibility constraints

- Inherit shared semantic tokens: Neutral + Quiet Lagoon light-only MVP, selected typography/control minima and 560px starting drawer. Do not treat sample comparison-board widths as responsive breakpoints or introduce dark mode. Runtime wrappers remain planned, not implemented.
- Use a route-addressable task with equivalent form state: modal right drawer on suitable desktop widths, full page on phones/narrow layouts. Preserve active field and input across transitions; trap focus and deactivate background only while modal. Direct URLs need a safe default return when no originating list exists.
- Preserve origin draft/filter/scroll context through authorized related-record navigation; revalidate dependent counts and access on return. Ordinary unsaved administrative forms need not survive refresh/closure. Employee autosave is a separate persistence contract.
- Confirmed employee submission returns to My Leave with list update, optional detail link and useful restored focus/announcement (ADR-0087). It does not inherit a generic “always open result details” route. Confirmed submission plus failed list refresh is still a successful submission.
- Preserve typed/keyboard date input and accessible disclosures; dates and durations are canonical business inputs, not invented exact half-day/hour times. Date-range errors never silently swap dates. Timeline bars select records and cannot drag/resize leave. Equivalent list views and selected-date semantics are required.
- Meet WCAG 2.2 AA through assembled-screen verification: associated field errors/summary, meaningful status announcements without keystroke chatter, focus restoration, no footer-obscured essential fields, readable zoom/reflow, keyboard and touch equivalence. Existing structural mocks and numeric contrast checks do not establish compliance.
- Mobile filter sheets have provisional state: Apply commits, Close/Back discards, Reset changes staged defaults. The badge counts changed groups, not options/results. Management tools sheets navigate immediately and have no Apply step. These distinctions belong in shared UI contracts, not Leave API state.

## Locale and presentation contracts

English is MVP; display examples use **15 Sep 2026**. Portuguese for Mozambique/Angola is planned separately. Language preference follows the person across NGOs, with English fallback for interface and personal notifications. Keep translation keys and safe typed error arguments independent of business branching, stored dates, employee work timezone and jurisdiction. Actual schedules govern durations; standard-day conversion must not become a global eight-hour assumption.

## Deliberate limits and delivery gates

The contracts do not authorize a generic workflow engine, shared personal task inbox, new directory synchronization, separate reporting service, durable offline edits, collaborative autosave merge or custom statutory engine. Prove reusable UI through Leave before promotion, while preserving service ownership and API boundaries.

Concrete responsive thresholds, wire error fields/compatibility, attachment association/cleanup protocol, draft lifecycle evidence retention, bounded coordination timeout and dependency-version mechanism remain affected-story decisions. They must satisfy the accepted behaviors above before those stories pass readiness; they need not become additional client setup options. This report makes no browser/assistive-technology, implementation or release-readiness claim.
